# of qname/qtype/qclass (so CHAOS-class probes, off-zone TXT probes,
# bind-chaos fingerprints, etc. all get the same boring REFUSED a
# regular off-zone authoritative would return).
#
# Comments start with '#'; blank lines are ignored. Both IPv4 and IPv6
# are accepted; bare addresses are equivalent to /32 (v4) or /128 (v6).
#
# Edit this file and run:
#   docker kill -s HUP honeycow
# to reload without restarting the container.
#
# Why this exists: the qname-based exemption list in exemptions.txt only
# catches scanners that probe their own canonical zone (e.g. Shadowserver
# asking for `dnsscan.shadowserver.org`). When a scanner fingerprints us
# via an unrelated qname (`TXT google.com`, `TXT version.bind`, etc.) we
# would otherwise answer — and that "yes I'm an open resolver" answer is
# exactly what gets fed into hosting-provider abuse pipelines. Refusing
# at the source IP closes that gap.
#
# All entries below are sourced from each organization's *published*
# scanner-IP documentation. Refresh periodically; lists drift.
